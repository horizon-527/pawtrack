# 真机实测与验收

目的：证明真实设备脱离电脑和手机网络，仍能将真实卫星位置上传，并在自己的微信小程序显示位置/轨迹。自动测试、模拟路线和固件编译不能代替此验收。所有表格初始状态是“待测”。

## 准备和记录

使用自己的 AppID/服务器和专用测试设备，装好天线与 SIM，用稳定 USB 供电。固件实际配置要与服务器同一套设备身份；小程序关闭演示。记录：测试日期、代码提交、PCB 版本、模组固件版本、SIM 运营商/APN、供电方式、测试地点类别、手机/微信版本、执行人。

不在公开仓库上传原始坐标或密钥。私人记录需包括：服务器 receivedAt 与设备 capturedAt、上传间隔、当前模式、在线/定位状态、断网起止、重启次数、缓存点数、电压/电流/Wh。电流与佩戴适配以实体测量为准。

以下数值是**首轮通过标准**，不是已实测指标。每项填写通过/失败、实际数值和证据。失败先排查再重测，不能用“编译成功”代签。

## D. 模组 TLS 的四组实测

这是硬件上线门槛，使用独立测试 CA 和自己控制的测试域名。**不向外部证书测试网站发送真实 deviceToken，也不关闭证书检查。** 项目提供可重复生成的本地 TLS 测试服务；电脑端正例、错误根、过期和错误域名已经自动测试，但模组端仍待实测。

1. 另准备一个测试域名，例如 `tls.你的域名`，DNS 指向可临时开放8443的测试机。生成证书，目录必须是新目录：

```sh
python3 tools/tls_lab.py generate --directory secrets/tls-lab --hostname tls.你的域名
python3 tools/tls_lab.py serve --directory secrets/tls-lab --mode valid --host 0.0.0.0 --port 8443
```

2. ESP 固件停止，模组用 AT 口操作，GNSS获取正确时间后设置模组 UTC 时钟。用 CA 导入工具把 `secrets/tls-lab/ca.pem` 装为 `pawtrack-lab.pem`。不要覆盖生产 CA。
3. 按手册设置：TLS1.2、authmode=1、ignorelocaltime=0、enableSNI=1、cacert=pawtrack-lab.pem；HTTPINIT，HTTPPARA的SSLCFG=0、URL=`https://tls.你的域名:8443/health`，HTTPACTION=0（GET）。不设置 Authorization。
   对应AT指令如下；域名须替换，模组时间须从实际GNSS UTC设置好：

```text
AT+CSSLCFG="sslversion",0,3
AT+CSSLCFG="authmode",0,1
AT+CSSLCFG="ignorelocaltime",0,0
AT+CSSLCFG="enableSNI",0,1
AT+CSSLCFG="cacert",0,"pawtrack-lab.pem"
AT+HTTPINIT
AT+HTTPPARA="SSLCFG",0
AT+HTTPPARA="URL","https://tls.你的域名:8443/health"
AT+HTTPACTION=0
AT+HTTPTERM
```

4. 完成表中四组。每次切服务先 Ctrl+C 停止，再用相同命令更改 `--mode`；域名、端口、时间和网络保持相同。

| 组别 | 服务证书/模组信任根 | 期望 |
|---|---|---|
| T01 正例 | --mode valid，信任ca.pem | 请求成功，HTTP 200 |
| T02 错误根 | --mode valid，把untrusted-ca.pem导入独立文件并选择它 | TLS失败，不能出现有效HTTP 200 |
| T03 过期 | --mode expired，重新选择正确ca.pem | TLS失败；此时主机名和CA正确 |
| T04 错误域名 | --mode wrong-host，信任正确ca.pem，URL仍是原测试域名 | TLS失败；证书有效但SAN只覆盖wrong.原域名 |

记录模块版本、设置、返回码，不记录真实设备密钥。T04如果竟然成功，说明该模组/配置没有满足本项目主机名验证要求：该硬件不得投入真实使用，通信实现需要迁移到经过验收的 PPP + ESP-TLS。完成后恢复生产 CA 配置与正式固件，关闭测试端口，测试私钥不发布。
